# План

Пересмотрен 25 сентября 2026 года. Прежний план («read-only чаты», 22 сентября)
в основном выполнен и перерос сам себя: клиент отправляет, удаляет и пересылает
сообщения, ищет по Telegram и по локальному кешу. Новое направление — перенос
функций из форков Telegram Desktop: [AyuGram](https://github.com/AyuGram/AyuGramDesktop)
и [materialgram](https://github.com/kukuruzka165/materialgram). Их исходников в репозитории
нет: когда они нужны, их клонируют в корень без git-истории, в `ayugram/` и `materialgram/`,
которые игнорирует git (см. `AGENTS.md`, «Telegram Desktop sources»).

## Правила переноса

- **Переносим поведение, а не код.** AyuGram и materialgram — GPLv3, наш код —
  `Unlicense OR MIT`. Читать их исходники, чтобы понять поведение, правила и
  тексты, можно; переводить их код на Go, копировать иконки, звуки и темы — нет.
  Так уже сделаны значки Premium и проверки (см. README).
- **Тексты — из серверного языкового пакета.** Строки tdesktop (`lng_…`) берём
  через `TelegramKeys` со своими переводами на случай, если пакета нет. Строки
  AyuGram (`ayu_…`) в пакете Telegram отсутствуют — только свои переводы.
- **Смотреть оба форка:** функция может быть собственной у одного из них
  (снимок сообщений — AyuGram, `ayu/features/message_shot`).
- **UI — из своих компонентов** (`docs/UI_COMPONENTS.md`), с проверкой на
  скриншотах, а не только тестами.
- **Аккаунты пользователя настоящие.** Изменяющие вызовы проверять только с его
  разрешения; поиск публичных постов тратит бесплатные поиски.

## Что уже есть

**Аккаунты и защита.** Вход по телефону, коду и 2FA; импорт tdata; несколько
аккаунтов со своими окнами; выход с завершением сеанса. TPM 2.0 + мастер-пароль,
зашифрованные сессии и SQLite (Adiantum). Одно соединение на ключ; загрузки с
домашнего DC — через медиа-адреса. Мёртвая сессия (`AUTH_KEY_DUPLICATED`,
`SESSION_REVOKED` и др.) и заморозка аккаунта показываются диалогами, аккаунт не
удаляется сам.

**История и кеш.** Постраничная загрузка в обе стороны, офлайн-чтение из SQLite,
live-updates (new/edit/delete), якорь прокрутки и кеш высот, переход к
сообщению (`Store.Reveal`) с защитой от устаревших страниц.

**Сообщения.** Группы сообщений одного автора, пузыри в стиле materialgram,
цитаты ответов с переходом, «Переслано от…», реакции (только показ), просмотры,
подпись и комментарии постов, альбомы, фото/GIF/стикеры/Lottie/WebM/custom emoji,
видео и аудио через mpv или VLC, файлы, опросы, кнопки-ссылки ботов, спойлеры,
выделение текста и сообщений.

**Действия.** Отправка текста, файлов, стикеров, GIF, чек-листов, ответы;
удаление и пересылка с проверкой прав как в tdesktop; снимок выбранных
сообщений в PNG; контекстное меню сообщения.

**Поиск.** Глобальный (чаты, каналы, посты, медиа по разделам) и локальный по
FTS5-индексу кеша — работает без сети. История поиска (недавние чаты), как у
tdesktop.

**Прочее.** Профиль и его редактирование, настройки (с разделом «Устройства» —
список сеансов, без их завершения), темы чатов, общие медиа,
трей, профилировщик, отчёты о падениях, приватный режим экрана.

## Порт из AyuGram и materialgram

Порядок — от того, что меняет повседневное чтение, к удобствам. Пути — внутри
`Telegram/SourceFiles` локальных клонов `ayugram/` и `materialgram/`.

### 0. Начать с этого: наборы стикеров и emoji, контекстное меню сообщения

Раздел выполнен 25 сентября 2026 года. Пути — в исходниках обоих форков
(общая база tdesktop).

- [x] **Ссылка на набор в модели.** Стикер в сообщении хранит свой набор
      (`DocumentAttributeSticker.Stickerset`); для custom emoji из текста набор
      узнаётся по документам (`messages.getCustomEmojiDocuments`, атрибут
      `DocumentAttributeCustomEmoji.Stickerset`).
- [x] **Диалог набора стикеров** по обычному клику на стикер в чате: название,
      число стикеров (`lng_stickers_count`), сетка с анимацией, кнопка
      «Добавить стикеры» (`lng_stickers_add_pack`) / «Удалить» для уже
      установленного (`lng_stickers_remove_pack_confirm`, как у materialgram —
      вместо «Поделиться»). Загрузка — `messages.getStickerSet`; установка и
      удаление (`messages.installStickerSet`/`uninstallStickerSet`) — изменяющие
      вызовы, проверять вживую только с разрешения пользователя.
      `boxes/sticker_set_box.cpp`.
- [x] **Тот же диалог для набора emoji**: сетка эмодзи, `lng_custom_emoji_count`.
- [x] **Контекстное меню сообщения** по правому клику: ответить, копировать
      текст, копировать ссылку (для публичных чатов), переслать, выбрать,
      удалить — с теми же правами, что у кнопок над выделением

- [x] **Пункт меню «Наборы emoji»** для сообщений с custom emoji: «Это сообщение
      содержит эмодзи из набора X» / «…из N наборов» (`lng_context_animated_emoji`,
      `lng_context_animated_emoji_many`); выбор открывает список наборов, а набор —
      диалог из пункта выше.

### 1. Чтение (оба форка, база tdesktop)

- [x] **Служебные сообщения текстом действия** («X вступил в группу», закреп,
      смена названия…) вместо «Служебное сообщение». `history/history_item.cpp` (`HistoryItem::prepareServiceTextForMessage`),
      строки `lng_action_*`. Действие хранится в `model.ServiceAction`,
      текст собирает UI на своём языке; звонки — пузырём. Действия, которых
      нет в `serviceAction` (подарки Premium, розыгрыши, платежи…), остаются
      «Служебным сообщением». Сообщения из старого кеша получат действие
      при перезагрузке с сервера.
- [x] **Закреплённое сообщение** под шапкой чата с переходом к нему и
      переключением между несколькими. `history/view/history_view_pinned_bar.cpp`.
      Последние 100 закрепов (`messages.search` с фильтром закреплённых),
      обновления `UpdatePinned(Channel)Messages`; крестик скрывает полосу до
      нового закрепа, как у участника в tdesktop. Открепление (изменяющий
      вызов) и правый клик (следующий закреп) не перенесены.
- [x] **Ответ на незагруженное сообщение:** подгружать его (`messages.getMessages` /
      `channels.getMessages`) вместо заглушки «Сообщение». `model.MessageLookup`:
      сначала кеш истории, затем Telegram; найденное хранится отдельно от
      истории (`lookup/<чат>/<id>` в кеше), удаление помечает его удалённым.
      Тем же путём закреп называет закреплённое сообщение.
- [x] **Реакции по клику** и обновление реакций/просмотров из updates
      (`UpdateMessageReactions`, `UpdateChannelMessageViews`); полоса
      реакций в контекстном меню. Отправка (`messages.sendReaction`) вживую
      не проверялась — изменяющий вызов.
- [x] **Комментарии к постам:** полоса комментариев (как у materialgram)
      открывает обсуждение (thread). Отправка комментария вживую не
      проверялась.
- [x] **Каналы без подписки** обновляются, пока открыты (опрос
      `updates.getChannelDifference`, как у tdesktop).
- [x] **Реакции:** премиальные и custom emoji реакции в полосе меню, быстрая
      реакция двойным кликом, список поставивших. Custom emoji — из топа
      реакций аккаунта (`messages.getTopReactions`), без выбора из всех
      наборов; двойной клик по пузырю вне текста ставит реакцию по умолчанию
      (`reactions_default` из `help.getConfig`); «N реакций» в меню открывает
      список (`messages.getMessageReactionsList`) с вкладками по реакциям.
      Постановка реакции вживую не проверялась — изменяющий вызов.
- [x] **Шапка чата:** поиск по чату (`messages.search`), меню чата. Поиск —
      поле поверх шапки со счётчиком «N из M» и переходами к более ранним и
      поздним найденным (Enter — к более раннему, как у tdesktop), офлайн —
      по FTS5-индексу кеша; найденное сообщение подсвечивается. Меню —
      только неизменяющие пункты: поиск, информация о чате, «К началу»
      (AyuGram). Звук, очистка истории, выход — изменяющие, не перенесены.

### 2. Приватность (AyuGram)

По умолчанию клиент ведёт себя как Telegram: отмечает прочитанное, показывает
«в сети» и «печатает». Не отправлять что-то из этого — это и есть «режим
призрака», он включается в настройках. Переносить стоит то, что поверх него.

- [x] **Режим призрака как настройка:** явные переключатели (прочтение, онлайн,
      набор, загрузка) и «прочитать» по действию пользователя, когда он хочет.
      `ayu/ayu_settings.h` (`sendReadMessages`, `sendOnlinePackets`…).
      «Приватность → Режим призрака»: прочтение (что показано в истории),
      «в сети» (пока окно в фокусе), «печатает», «прочитывать при действии»
      (отправка, реакция; включено по умолчанию, как у AyuGram); пункт меню
      «Прочитать». Все три переключателя по умолчанию включены (раньше были
      выключены, и чаты не отмечались прочитанными вовсе); выбор хранится и
      когда выключен (`send_read`… без `omitempty`). Одни настройки для всех аккаунтов; прогресс загрузки
      (`sendUploadProgress`) не отправляется вовсе. Вызовы изменяющие —
      вживую не проверялись.
- [x] **Сохранение удалённых и истории правок.** Наш кеш уже помнит сообщения —
      не стирать их при удалении, а помечать, и хранить прежние версии при
      правке; показывать отметкой (`deletedMark`, `editedMark`).
      `ayu/data/messages_storage.cpp`. Удалённое другими (updates и сверка
      страниц) остаётся в SQLite с `deleted=2` и `Deleted` в JSON, с отметкой
      «🧹»; чаты с ботами и свои удаления стирают, как у AyuGram. Правки чужих
      сообщений хранят прежний текст (таблица `edits`), пункт меню «История
      правок». Обе настройки — «Приватность → Сохранение сообщений», включены
      по умолчанию. Удалённые не ищутся (FTS5 их не индексирует).
- [x] **Фильтры сообщений** (регулярные выражения, скрытие от заблокированных).
      `ayu/features/filters`. «Приватность → Фильтры сообщений»: выражения
      Go `regexp` (не ICU, как у AyuGram), «наоборот», без учёта регистра,
      общие или одного чата; без «в чатах» — только каналы; скрытие от
      заблокированных (`contacts.getBlocked`) — везде, кроме лички с ним.
      Свои сообщения не фильтруются; меню чата показывает скрытое; пункт
      «Добавить фильтр» для выделенного текста. Нет исключений общих
      фильтров для чата, «теневого бана», импорта и экспорта.
- [x] **Режим стримера:** скрывать личное на экране (у нас есть приватный режим —
      расширить). `ayu/features/streamer_mode`. Как у AyuGram — окна
      исключаются из захвата экрана (`SetWindowDisplayAffinity`), только на
      Windows: на X11/Wayland способа нет, macOS не сделан; переключатель
      есть только там, где работает. **Нужна проверка мейнтейнером на
      Windows.** Приватный режим теперь скрывает и IP-адреса устройств.

### 3. Внешний вид

Внешний вид только приближаем к materialgram, а не копируем: своя тема MD3
остаётся. Тему Material You с раскраской под акцент и шрифты (Google Sans,
выбор шрифта AyuGram) не переносим.

- [x] **Настройки вида (AyuGram):** радиус пузырей, скругление аватаров, секунды
      во времени сообщений, свои отметки «изменено»/«удалено».
      «Оформление → Сообщения и аватары» с предпросмотром; диапазоны как у
      AyuGram (радиус 0–16, скругление 0–23). Применяются без перезапуска.
- [x] **Снимок сообщений:** предпросмотр и выбор темы снимка
      (`ayu/ui/boxes/message_shot_box.cpp`); копирование в буфер (потребует
      поддержки изображений в буфере обмена форка Gio). Окно снимка: тема
      (как в приложении, светлая, тёмная — базовые схемы, без оформления
      чата), фон, дата, реакции, спойлеры; «Сохранить» и «Копировать».
      Буфер форка Gio принимает `image/png` на X11 (проверено вживую под
      Xvfb), Wayland и Windows (**нужна проверка мейнтейнером**), см.
      `third_party/gio/LOCAL_CHANGES.md`.

### 4. Удобства

- [x] **Перевод сообщений** (`messages.translateText`; у AyuGram ещё
      Google/Яндекс). `ayu/features/translator`. Пункты меню «Перевести» и
      «Перевести выделенное» открывают окно с переводом на язык интерфейса,
      как `TranslateBox` в tdesktop. Только Telegram: Google и Яндекс не
      перенесены; вживую не проверялось (Telegram может требовать Premium).
- [x] **Повтор сообщения («+1»)**, копирование `@username`, подтверждение перед
      отправкой стикера/GIF/голосового (AyuGram). «Повторить» в меню
      сообщения пересылает его в тот же чат (личные и группы, где можно
      писать и пересылать; не в каналах и не служебные). В сведениях чата с
      публичным именем — «@имя» и ссылка `t.me/имя`, копируются по щелчку.
      В «Оформлении» — «Подтверждать отправку» стикеров и GIF: выбранное в
      панели ждёт окна с предпросмотром. Голосовых нет, пока нет их записи.
      Вживую повтор не проверялся (он отправляет сообщение).
- [x] **Сведения:** дата-центр фото/файла, примерная дата создания аккаунта,
      счётчик онлайна в больших группах (materialgram). В сведениях чата —
      дата-центр фото профиля («DC 4, Amsterdam») и, у пользователей и ботов,
      дата регистрации, оценённая по ID между известными точками («~ 10.2023»,
      «раньше 09.2013», «позже 03.2024»); строки копируются по щелчку. Шапка
      группы — «N участников, M в сети» по `messages.getOnlines` (сервер считает
      всех, а не загруженных участников, как tdesktop), раз в минуту.
      Дата-центр файлов в сообщениях не показывается.
- [x] **Отправка фото и файлов как в tdesktop** (`boxes/send_files_box.cpp`,
      `ui/chat/attach`, `storage/localimageloader.cpp`). «Фото или видео» и
      «Файл» открывают выбор нескольких файлов и окно отправки: картинки
      сеткой (одна — в своей пропорции), остальное строками, подпись (текст
      из поля ввода — заготовка; Enter отправляет), «Сгруппировать»,
      «Отправить как файлы», «Высокое качество». Правила tdesktop в
      `internal/messenger/sendfiles`: альбом из фото и видео (файлы — свой
      альбом) до 10, GIF — отдельно; подпись на последнем сообщении, на
      первом снимке альбома; фото — поворот по Exif, вписывание в 1280 (2560
      в высоком качестве), JPEG q94 на белом фоне, JPEG без изменений уходит
      как есть; картинка вытянутее 1:20 — файл. Отправка: `messages.uploadMedia`
      и `sendMultiMedia`, у каждого сообщения свой `random_id` от общего, так
      что повтор после ошибки ничего не дублирует. Проверено вживую в демо
      (Linux, zenity): выбор нескольких файлов, альбом, подпись по Enter.
      Не сделано: вставка картинки и файлов из буфера (Ctrl+V), перетаскивание
      файлов в окно (нужны изменения форка Gio), правка картинки, спойлер,
      отправка по расписанию и без звука, прогресс загрузки.
- [x] **Mini Apps** (`pkg/miniapp`, `internal/messenger/miniapps`). Готовый
      мост к Chromium пользователя (CDP) подключён к Telegram: кнопки
      `WebView` и `SimpleWebView` под сообщением и в клавиатуре бота и кнопка
      меню бота у поля ввода (`BotInfo.MenuButton`) просят ссылку
      (`messages.requestWebView` / `requestSimpleWebView`, платформа
      `tdesktop`, цвета окна как `themeParams`), открывают её в браузере с
      профилем по настройке «Mini Apps» (не хранить / на приложение / общий на
      аккаунт) и обслуживают приложение: `web_app_close`, `open_link`,
      `open_tg_link` (ссылка идёт в обычное подтверждение), `request_theme`,
      `request_viewport`, `data_send` (`messages.sendWebViewData`, приложение
      закрывается), главная и «назад» кнопки рисуются внутри страницы
      (вокруг окна браузера рисовать нельзя), `invoke_custom_method`,
      запросы записи и телефона получают отказ, чтобы не висеть;
      внутренний запрос продлевается `messages.prolongWebView`. Вживую
      (Linux/X11, демо, Chromium 141 под root с `--no-sandbox`): меню-кнопка
      открывает встроенное приложение с init data и темой, главная кнопка
      рисуется и нажимается, `sendData` уходит и закрывает приложение.
      Не проверялось на реальном боте (`requestWebView` идёт от имени
      аккаунта). Не сделано: главное приложение бота
      (`messages.requestMainWebView`), ссылки `t.me/бот/приложение`,
      облачное хранилище приложения (`CloudStorage`, отвечаем «нет метода»),
      всплывающие окна приложения (`showPopup`, закрываются без выбора),
      буфер обмена, шапка и цвета окна приложения, вторая копия окна одного
      приложения (профиль занят).
- [x] **Боты** (`messages.getBotCallbackAnswer`). Кнопки под сообщением бота
      работают: callback-кнопка спрашивает бота и показывает его ответ тостом
      (у ответа со ссылкой предлагает открыть её; молчащий бот и ошибка тоже
      называются тостом), «…» на кнопке, пока бот думает; кнопка «копировать»
      кладёт текст в буфер; ссылки — как раньше. Клавиатура ответа
      (`ReplyKeyboardMarkup`) встаёт под полем ввода: клавиши шлют свой текст,
      «×» прячет её до новой; её убирает сообщение с `ReplyKeyboardHide`, а
      одноразовую — первое же своё сообщение после неё. В пустом чате с ботом
      вместо поля ввода кнопка «Запустить» (`/start`, как в tdesktop). В чате с
      ботом набор «/…» открывает список его команд (`users.getFullUser`,
      `BotInfo.Commands`); клик отправляет команду. Вживую в демо (Linux/X11):
      все кнопки, клавиатура, Start, команды. На реальном боте не проверялось —
      `getBotCallbackAnswer` и отправка меняют состояние бота. Не сделано:
      inline-режим (`@бот запрос`, `switch_inline`), `request_phone/geo/poll`,
      `url_auth`, игры и оплата, callback с паролем (кнопка выключена),
      предупреждение бота окном (оно идёт тостом), подсказка поля ввода из
      клавиатуры, кнопка «/» у поля ввода, команды по чатам групп.
- [x] **Закрепление чатов** (`messages.toggleDialogPin`). Правый клик по чату в
      списке «Все чаты» открывает меню: «Закрепить»/«Открепить» и, если есть
      непрочитанное, «Прочитано» (как в tdesktop, `window_peer_menu.cpp`).
      Закреплённый чат без непрочитанного показывает булавку. Закрепы идут в
      порядке закрепления (`Chat.PinRank`, прежде они сортировались по
      времени сообщения и «прыгали»); новый закреп встаёт первым, как в
      Telegram. Лимит — `dialogs_pinned_limit` из конфигурации сервера (5, с
      Premium 10): сверх него запрос не отправляется, тост называет лимит и
      то, что даёт Premium; ответ `PINNED_DIALOGS_TOO_MUCH` тоже. Локальный
      Premium лимит не поднимает: он только рисует звезду, а лимит проверяет
      сервер. Закрепы, сделанные в других клиентах, приходят обновлениями
      (`updateDialogPinned`, `updatePinnedDialogs`). Не сделано: закрепы папок
      и архива, перестановка перетаскиванием. Вживую в демо (Linux/X11)
      проверено; вызов `toggleDialogPin` на реальном аккаунте не проверялся.
- [x] **Форумы** (темы супергрупп, `messages.getForumTopics`). Чат-форум
      открывается списком тем, как в tdesktop: значок цвета темы с «#» (General —
      домик, custom emoji — свой значок), название, замок у закрытой, время,
      последнее сообщение с автором, счётчики непрочитанного и упоминаний
      (у заглушённой — серый), булавка у закреплённой темы. Тема открывается
      страницей обсуждения (как комментарии к посту, `commentsView`) со
      стрелкой назад; сообщения — `messages.getReplies` по корню темы, отправка —
      в группу с `reply_to` на корень (General — без корня). Список темы
      обновляется по приходящим сообщениям (последнее сообщение, счётчик,
      порядок); открытая тема отмечается прочитанной `messages.readDiscussion`
      (с учётом режима призрака). Шапка форума открывает сведения о группе.
      Проверено вживую в демо (Linux/X11): список, открытие темы, назад,
      сведения. Не проверялось на реальном аккаунте: отправка в тему,
      `readDiscussion`. Не сделано: создание, закрытие и правка тем, вид «тем
      во вкладках» и «форум как список чатов», значок форума в списке чатов,
      пересылка из темы.
- [x] **Локальный Premium** (AyuGram, `localPremium`). Переключатель в
      разделе «Telegram Premium» настроек. Пока он включён, аккаунты, вошедшие
      в это приложение, видят звезду Premium у своих имён (список чатов, шапка,
      профиль, боковое меню, список аккаунтов), а раздел Premium говорит, что
      звезда локальная. Как в AyuGram, это только вид: Telegram об этом не
      знает, поэтому лимиты, реакции, эмодзи и размер загрузки остаются
      настоящими (иначе сервер отвечал бы ошибками), а другие звезды не видят.
      Звезда рисуется у пользователей из `Badges.User` — своих аккаунтов
      (`App.localPremium`); чужие и каналы не затронуты.
- [x] **Голосовые сообщения:** запись и отправка (нужен захват звука).
      Звук пишет внешний `ffmpeg`, как видео играет внешний плеер
      (`pkg/voice`): PulseAudio/PipeWire, затем ALSA на Linux, DirectShow на
      Windows, AVFoundation на macOS. При пустом поле вместо «Отправить» —
      микрофон; запись идёт «закреплённой», как в tdesktop: время, уровень,
      ✕ или Escape отменяют, «Отправить» кодирует в Opus/OGG и шлёт с
      длительностью и волной (`DocumentAttributeAudio`). Без ffmpeg — ошибка
      с просьбой установить его. Проверено на синтетическом входе `lavfi`
      (в контейнере нет микрофона); настоящий микрофон, Windows и macOS —
      **нужна проверка мейнтейнером**, отправка вживую не проверялась.
      Без ffmpeg микрофон открывает выбор аудиофайла (Opus/OGG, MP3, M4A),
      который уходит голосовым.
- [x] **Голосовые сообщения: прослушивание в клиенте.** Волна, которую
      присылает Telegram, кнопка ▶/⏸, прослушанная часть волны, время;
      клик или протяжка по волне перематывают. Без ffmpeg и внешнего плеера:
      libopus в wasm (`pkg/opus`), вывод через oto (`pkg/audio`). Голосовому
      без волны (боты, сервисы) она считается, как только оно на экране, как
      в tdesktop. MP3-голосовые — через dr_mp3 в wasm (`pkg/drdec`, там же
      dr_flac и dr_wav); M4A — через fdk-aac в wasm, который скачивается из
      отдельного репозитория fdk-aac-wasm (патенты на AAC).
- [x] **Музыка в клиенте.** Строка трека (название, исполнитель, полоса
      перемотки, время), проигрывание во время загрузки: декодеры читают
      файл по частям через `MediaStream`, остальное докачивается впереди.
      FLAC и WAV — через dr_libs; Vorbis и прочее — во внешнем плеере.
      Настройка «Плеер голосовых сообщений и музыки»: встроенный или внешний.
- [ ] **Мини-плеер над чатом** (для голосовых и музыки): что играет, когда
      сообщение ушло с экрана, пауза, ✕; продолжение при смене чата
      (сейчас звук останавливается).
- [ ] **Голосовые и музыка: дальше.** Следующее непрослушанное голосовое
      (и следующий трек) по окончании; скорость 1×/1,5×/2×; отметка «прослушано»
      (`messages.readMessageContents`, с оглядкой на Ghost); ширина пузыря по
      длительности, как в tdesktop; посчитанная волна — в кеш.

## Технические долги

- [ ] **Загрузчик истории:** узкий RPC-интерфейс и fake-матрица пагинации
      (first/older/newer, 0/1/limit, все варианты ответа, отмена при смене чата);
      `HasOlder` — по длине страницы, а не по количеству на сервере.
- [ ] **Пиры:** явная проверка access hash, min/forbidden/deleted; права пиров из
      старого кеша неизвестны, пока пир не обновится с сервера.
- [ ] **Лимиты кеша:** окно сообщений в памяти, политика хранения SQLite,
      миграции схемы, проверка целостности (у Adiantum нет MAC страниц).
- [ ] **Updates:** точечный resync каналов вместо `refreshOpen`, gaps, unread;
      `HandleAffected` для изменяющих вызовов.
- [ ] **Ошибка запуска аккаунта**, кроме мёртвой сессии и заморозки, только
      пишется в лог — нужен экран восстановления подключения.
- [x] **Перенос строк O(L²) при промахе кеша шейпера** (`styledtext`): шейпить
      абзац один раз без `MaxLines` и резать по `FlagLineBreak`
      (`BenchmarkHistoryLongPosts/resize` ≈ 3,6 мс/кадр).
      Сделано иначе, без переписывания итератора: строка шейпится из начала
      спана, заведомо длиннее строки (4 руны на em ширины, до пробела), и из
      всего спана, только если начало влезло целиком (`linePrefix`,
      `TestLinePrefixWrapsAsWholeSpan` сверяет с полным шейпингом). Профиль
      показал и вторую причину: оценка высоты считала руны всех сообщений на
      каждом пересчёте — теперь кеш по ревизии. На этой машине resize
      1,69 → 0,71 мс/кадр, аллокации 1789 → 729; steady 0,60 → 0,49 мс.
- [ ] **Фото:** серверная галерея, когда кеш кончился (`messages.search` с
      фильтром фото); сохранение и копирование из просмотрщика; подписи, GIF и
      видео в просмотрщике.
      Сделано: сохранение и копирование — кнопки в панели и Ctrl+S / Ctrl+C,
      как в tdesktop; оригинал ложится в «Изображения», в буфер — PNG; у фото
      из защищённых чатов кнопок нет. Осталось: серверная галерея, подписи,
      GIF и видео.
- [ ] **Прозрачность окна на X11:** 32-битный visual и EGL-конфиг под него
      (`internal/egl`, общий с Android — проверять вместе со сборкой под Android).
- [x] **Нестабильный тест** `chatmedia.TestAnimationStopsOffscreenWithoutDroppingFrame`
      (однажды упал под `-race`).
      Воспроизводился под `-race` с 4 параллельными прогонами (~1 из 300): при
      перезапуске анимации новая загрузка 8×8 PNG успевала опубликовать свой
      кадр раньше, чем `Frame` возвращал сохранённый, — а тест сравнивал
      указатели. Код верен; тест теперь держит повторную загрузку, пока не
      проверит кадр (1200 прогонов без падений, без сохранения кадра падает).
- [ ] **Старый кеш:** сообщения, закешированные до новых полей (варианты фото,
      реакции, просмотры, `NoForwards`), получают их только при перезагрузке с
      сервера. Так же и полоса комментариев (`CommentsOpen`, `Commenters`).
