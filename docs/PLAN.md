# План

Пересмотрен 25 сентября 2026 года. Прежний план («read-only чаты», 22 сентября)
в основном выполнен и перерос сам себя: клиент отправляет, удаляет и пересылает
сообщения, ищет по Telegram и по локальному кешу. Новое направление — перенос
функций из форков Telegram Desktop: [AyuGram](ayugram/) и [materialgram](materialgram/).
Их исходники лежат в корне репозитория без git-истории (версии — в `AGENTS.md`).

## Правила переноса

- **Переносим поведение, а не код.** AyuGram и materialgram — GPLv3, наш код —
  `Unlicense OR MIT`. Читать их исходники, чтобы понять поведение, правила и
  тексты, можно; переводить их код на Go, копировать иконки, звуки и темы — нет.
  Так уже сделаны значки Premium и проверки (см. README).
- **Тексты — из серверного языкового пакета.** Строки tdesktop (`lng_…`) берём
  через `TelegramKeys` со своими переводами на случай, если пакета нет. Строки
  AyuGram (`ayu_…`) в пакете Telegram отсутствуют — только свои переводы.
- **Смотреть оба форка:** функция может быть собственной у одного из них
  (снимок сообщений — AyuGram, `ayu/features/message_shot`).
- **UI — из своих компонентов** (`docs/UI_COMPONENTS.md`), с проверкой на
  скриншотах, а не только тестами.
- **Аккаунты пользователя настоящие.** Изменяющие вызовы проверять только с его
  разрешения; поиск публичных постов тратит бесплатные поиски.

## Что уже есть

**Аккаунты и защита.** Вход по телефону, коду и 2FA; импорт tdata; несколько
аккаунтов со своими окнами; выход с завершением сеанса. TPM 2.0 + мастер-пароль,
зашифрованные сессии и SQLite (Adiantum). Одно соединение на ключ; загрузки с
домашнего DC — через медиа-адреса. Мёртвая сессия (`AUTH_KEY_DUPLICATED`,
`SESSION_REVOKED` и др.) и заморозка аккаунта показываются диалогами, аккаунт не
удаляется сам.

**История и кеш.** Постраничная загрузка в обе стороны, офлайн-чтение из SQLite,
live-updates (new/edit/delete), якорь прокрутки и кеш высот, переход к
сообщению (`Store.Reveal`) с защитой от устаревших страниц.

**Сообщения.** Группы сообщений одного автора, пузыри в стиле materialgram,
цитаты ответов с переходом, «Переслано от…», реакции (только показ), просмотры,
подпись и комментарии постов, альбомы, фото/GIF/стикеры/Lottie/WebM/custom emoji,
видео и аудио через mpv или VLC, файлы, опросы, кнопки-ссылки ботов, спойлеры,
выделение текста и сообщений.

**Действия.** Отправка текста, файлов, стикеров, GIF, чек-листов, ответы;
удаление и пересылка с проверкой прав как в tdesktop; снимок выбранных
сообщений в PNG; контекстное меню сообщения.

**Поиск.** Глобальный (чаты, каналы, посты, медиа по разделам) и локальный по
FTS5-индексу кеша — работает без сети. История поиска (недавние чаты), как у
tdesktop.

**Прочее.** Профиль и его редактирование, настройки (с разделом «Устройства» —
список сеансов, без их завершения), темы чатов, общие медиа,
трей, профилировщик, отчёты о падениях, приватный режим экрана.

## Порт из AyuGram и materialgram

Порядок — от того, что меняет повседневное чтение, к удобствам. Пути — внутри
`ayugram/Telegram/SourceFiles` и `materialgram/Telegram/SourceFiles`.

### 0. Начать с этого: наборы стикеров и emoji, контекстное меню сообщения

Раздел выполнен 25 сентября 2026 года. Пути — в исходниках обоих форков
(общая база tdesktop).

- [x] **Ссылка на набор в модели.** Стикер в сообщении хранит свой набор
      (`DocumentAttributeSticker.Stickerset`); для custom emoji из текста набор
      узнаётся по документам (`messages.getCustomEmojiDocuments`, атрибут
      `DocumentAttributeCustomEmoji.Stickerset`).
- [x] **Диалог набора стикеров** по обычному клику на стикер в чате: название,
      число стикеров (`lng_stickers_count`), сетка с анимацией, кнопка
      «Добавить стикеры» (`lng_stickers_add_pack`) / «Удалить» для уже
      установленного (`lng_stickers_remove_pack_confirm`, как у materialgram —
      вместо «Поделиться»). Загрузка — `messages.getStickerSet`; установка и
      удаление (`messages.installStickerSet`/`uninstallStickerSet`) — изменяющие
      вызовы, проверять вживую только с разрешения пользователя.
      `boxes/sticker_set_box.cpp`.
- [x] **Тот же диалог для набора emoji**: сетка эмодзи, `lng_custom_emoji_count`.
- [x] **Контекстное меню сообщения** по правому клику: ответить, копировать
      текст, копировать ссылку (для публичных чатов), переслать, выбрать,
      удалить — с теми же правами, что у кнопок над выделением
      (`model.RightsSource`). Меню — наш `contextMenu`.
      `history/view/history_view_context_menu.cpp`. Ответ — полоса над
      композером (`lng_preview_reply_to`); ссылка, как у tdesktop, есть у
      каналов и супергрупп: публичная или `t.me/c/…` для участников.
- [x] **Пункт меню «Наборы emoji»** для сообщений с custom emoji: «Это сообщение
      содержит эмодзи из набора X» / «…из N наборов» (`lng_context_animated_emoji`,
      `lng_context_animated_emoji_many`); выбор открывает список наборов, а набор —
      диалог из пункта выше.

### 1. Чтение (оба форка, база tdesktop)

- [x] **Служебные сообщения текстом действия** («X вступил в группу», закреп,
      смена названия…) вместо «Служебное сообщение». `history/history_item.cpp` (`HistoryItem::prepareServiceTextForMessage`),
      строки `lng_action_*`. Действие хранится в `model.ServiceAction`,
      текст собирает UI на своём языке; звонки — пузырём. Действия, которых
      нет в `serviceAction` (подарки Premium, розыгрыши, платежи…), остаются
      «Служебным сообщением». Сообщения из старого кеша получат действие
      при перезагрузке с сервера.
- [ ] **Закреплённое сообщение** под шапкой чата с переходом к нему и
      переключением между несколькими. `history/view/history_view_pinned_bar.cpp`.
- [ ] **Ответ на незагруженное сообщение:** подгружать его (`messages.getMessages` /
      `channels.getMessages`) вместо заглушки «Сообщение».
- [x] **Реакции по клику** и обновление реакций/просмотров из updates
      (`UpdateMessageReactions`, `UpdateChannelMessageViews`); полоса
      реакций в контекстном меню. Отправка (`messages.sendReaction`) вживую
      не проверялась — изменяющий вызов.
- [x] **Комментарии к постам:** полоса комментариев (как у materialgram)
      открывает обсуждение (thread). Отправка комментария вживую не
      проверялась.
- [x] **Каналы без подписки** обновляются, пока открыты (опрос
      `updates.getChannelDifference`, как у tdesktop).
- [ ] **Реакции:** премиальные и custom emoji реакции в полосе меню, быстрая
      реакция двойным кликом, список поставивших.
- [ ] **Шапка чата:** поиск по чату (`messages.search`), меню чата.

### 2. Приватность (AyuGram)

У нас по умолчанию уже не отправляются прочтение, «в сети» и набор текста — это
и есть «режим призрака». Переносить стоит то, что поверх него.

- [ ] **Режим призрака как настройка:** явные переключатели (прочтение, онлайн,
      набор, загрузка) и «прочитать» по действию пользователя, когда он хочет.
      `ayu/ayu_settings.h` (`sendReadMessages`, `sendOnlinePackets`…).
- [ ] **Сохранение удалённых и истории правок.** Наш кеш уже помнит сообщения —
      не стирать их при удалении, а помечать, и хранить прежние версии при
      правке; показывать отметкой (`deletedMark`, `editedMark`).
      `ayu/data/messages_storage.cpp`.
- [ ] **Фильтры сообщений** (регулярные выражения, скрытие от заблокированных).
      `ayu/features/filters`.
- [ ] **Режим стримера:** скрывать личное на экране (у нас есть приватный режим —
      расширить). `ayu/features/streamer_mode`.

### 3. Внешний вид

Внешний вид только приближаем к materialgram, а не копируем: своя тема MD3
остаётся. Тему Material You с раскраской под акцент и шрифты (Google Sans,
выбор шрифта AyuGram) не переносим.

- [ ] **Настройки вида (AyuGram):** радиус пузырей, скругление аватаров, секунды
      во времени сообщений, свои отметки «изменено»/«удалено».
- [ ] **Снимок сообщений:** предпросмотр и выбор темы снимка
      (`ayu/ui/boxes/message_shot_box.cpp`); копирование в буфер (потребует
      поддержки изображений в буфере обмена форка Gio).

### 4. Удобства

- [ ] **Перевод сообщений** (`messages.translateText`; у AyuGram ещё
      Google/Яндекс). `ayu/features/translator`.
- [ ] **Повтор сообщения («+1»)**, копирование `@username`, подтверждение перед
      отправкой стикера/GIF/голосового (AyuGram).
- [ ] **Сведения:** дата-центр фото/файла, примерная дата создания аккаунта,
      счётчик онлайна в больших группах (materialgram).
- [ ] **Голосовые сообщения:** запись и отправка (нужен захват звука).

## Технические долги

- [ ] **Загрузчик истории:** узкий RPC-интерфейс и fake-матрица пагинации
      (first/older/newer, 0/1/limit, все варианты ответа, отмена при смене чата);
      `HasOlder` — по длине страницы, а не по количеству на сервере.
- [ ] **Пиры:** явная проверка access hash, min/forbidden/deleted; права пиров из
      старого кеша неизвестны, пока пир не обновится с сервера.
- [ ] **Лимиты кеша:** окно сообщений в памяти, политика хранения SQLite,
      миграции схемы, проверка целостности (у Adiantum нет MAC страниц).
- [ ] **Updates:** точечный resync каналов вместо `refreshOpen`, gaps, unread;
      `HandleAffected` для изменяющих вызовов.
- [ ] **Ошибка запуска аккаунта**, кроме мёртвой сессии и заморозки, только
      пишется в лог — нужен экран восстановления подключения.
- [ ] **Перенос строк O(L²) при промахе кеша шейпера** (`styledtext`): шейпить
      абзац один раз без `MaxLines` и резать по `FlagLineBreak`
      (`BenchmarkHistoryLongPosts/resize` ≈ 3,6 мс/кадр).
- [ ] **Фото:** серверная галерея, когда кеш кончился (`messages.search` с
      фильтром фото); сохранение и копирование из просмотрщика; подписи, GIF и
      видео в просмотрщике.
- [ ] **Прозрачность окна на X11:** 32-битный visual и EGL-конфиг под него
      (`internal/egl`, общий с Android — проверять вместе со сборкой под Android).
- [ ] **Нестабильный тест** `chatmedia.TestAnimationStopsOffscreenWithoutDroppingFrame`
      (однажды упал под `-race`).
- [ ] **Старый кеш:** сообщения, закешированные до новых полей (варианты фото,
      реакции, просмотры, `NoForwards`), получают их только при перезагрузке с
      сервера. Так же и полоса комментариев (`CommentsOpen`, `Commenters`).
